# Extended IT Glossary & Architecture Matrix

## Core Systems, Terminology & Migration Concepts

---

| Term / Concept                                     | Domain / Category                  | Technical Definition                                                                                                                                                                                               | Plain English & Analogy                                                                                                                                     | Practical Systems Context                                                                                                                                                   | Operational Notes & Best Practices                                                                                                                                  |
| :------------------------------------------------- | :--------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **A/B Testing**                                    | Feature Deployment / Analytics     | A randomized experiment where two variants of a system or interface (A and B) are compared to determine which performs better.                                                                                     | Showing half your users a blue button and the other half a red button, and tracking the data to see which one gets clicked more.                            | Utilized in web UI updates or canary deployment paths to evaluate user conversion or system throughput under split traffic.                                                 | Ensure statistically significant sample sizes and isolate environmental variables so metric deltas reflect actual performance differences.                          |
| **Backlog**                                        | Agile / ITSM / Work Allocation     | A prioritized inventory of functional/technical requirements, bug fixes, infrastructure tasks, and engineering debt awaiting execution.                                                                            | A master "to-do list" ordered strictly by priority, where high-value, urgent tasks stay at the top ready to be worked on next.                              | Managing system enhancement tickets, OS patch deployments, infrastructure upgrades, and refactoring tasks in tracking systems.                                              | Regularly groom and re-prioritize the backlog to purge obsolete items; ensure every ticket has clear acceptance criteria before execution.                          |
| **Deployment**                                     | DevOps / CI/CD Release             | The process of pushing software updates or applications from a testing environment into a live, production environment.                                                                                            | Taking an app or website out of the workshop and putting it into the real world for actual users to use.                                                    | Migrating validated code or configuration artifacts from local staging repos into active cloud or on-premise production servers.                                            | Always pair production releases with automated rollback triggers (blue-green/canary strategy) to minimize downtime if bugs occur.                                   |
| **ITIL**                                           | ITSM / Service Governance          | A globally recognized framework of best practices for Information Technology Service Management (ITSM).                                                                                                            | A massive, industry-standard rulebook on how to run an IT department efficiently so it actively supports the business instead of just putting out fires.    | Establishes standardized workflows for Incident Management, Problem RCA, Change Control, and Service Desk ticketing.                                                        | Focus on business value and continuous service improvement; avoid over-bureaucratizing rapid, low-risk administrative fixes.                                        |
| **Migration Checklist (Runbook / Playbook)**       | Systems Operations / Governance    | A manual or semi-automated, step-by-step operational guide and verification framework used to coordinate human actions, dependencies, and cutover windows during a migration.                                      | A pilot's pre-flight checklist that ensures every manual lever is checked and every team member knows their exact timing before takeoff.                    | Coordinating multi-team cutovers, verifying firewall rules, obtaining business sign-offs, and performing manual validation checks before triggering the automated pipeline. | Treat as a living document; audit and update the checklist after every dry run, and convert repetitive manual steps into automated pipeline code whenever possible. |
| **Migration Pipeline**                             | Infrastructure / CI/CD / DataOps   | An automated conveyor belt that safely packs up a system from the old environment, transports it, tests it, and sets it up in the new one without human intervention.                                              | Executing scripted database cutovers, cloud infrastructure lift-and-shift routines, or containerized application state migration using IaC and CI/CD tools. | Deploying automated validation scripts and state transfers.                                                                                                                 | Ensure full idempotency and build automatic rollback triggers (circuit breakers) into every pipeline stage to recover gracefully if validation fails.               |
| **Network Node**                                   | Computer Networking                | Any physical or logical connection point, redistribution point, or communication endpoint within a network structure.                                                                                              | Any single device (like a laptop, a router, a server, or a smart printer) that is plugged into the network and can "talk" to other devices.                 | Any endpoint device (e.g., `EP-WIN-01`, `EP-LIN-01`, `EP-MAC-01`) or managed switch assigned an IP/MAC address on the subnet.                                               | Maintain a clean static IP allocation matrix and enforce MAC filtering to prevent rogue endpoints from joining the internal subnet.                                 |
| **OSI Stack (Open Systems Interconnection Model)** | Computer Networking / Architecture | A conceptual framework split into 7 abstract layers (Physical, Data Link, Network, Transport, Session, Presentation, Application) used to standardize how different communication systems interact over a network. | A 7-story building through which every data packet travels: from the physical cable at the ground floor up to the user application at the top floor.        | Troubleshooting network latency, diagnosing packet drops, configuring firewall rules (e.g., L3/L4 vs. L7 filtering), and analyzing packet captures.                         | Always isolate connectivity issues layer by layer (start from Layer 1 physical/link up to Layer 7 application) during incident triage.                              |
| **Redundancy**                                     | High Availability / Systems        | The intentional duplication of critical system components or functions to increase reliability and prevent single points of failure.                                                                               | Carrying a spare tire in your trunk; you don't need it to drive normally, but it immediately saves you if a primary tire goes flat.                         | Implementing dual power supplies, RAID storage arrays, database replication, or redundant ISP failover links.                                                               | Perform periodic failover drills to verify that secondary backup systems initiate automatically without manual intervention.                                        |
| **Refactoring**                                    | Software Hygiene / Technical Debt  | Restructuring existing source code without changing its external behavior to improve readability and maintainability.                                                                                              | Cleaning up and organizing the "engine" of a program to make it run smoother and easier to fix later, without changing what the user sees.                  | Cleaning up monolithic Bash/PowerShell scripts into modular functions and removing obsolete logic during code reviews.                                                      | Execute comprehensive automated unit tests before and after refactoring to ensure system behavior remains 100% identical.                                           |
| **Resilience**                                     | System Architecture                | A system's capacity to withstand hardware or software failures and recover quickly to maintain continuous service.                                                                                                 | How well a system can take a punch, bounce back, and keep operating when things go wrong.                                                                   | Deploying self-healing container clusters, automated health probes, and circuit breakers that isolate failing services.                                                     | Design under a "maintenance mindset" that assumes hardware will eventually fail; track Mean Time to Recovery (MTTR) as a primary metric.                            |
| **SOC (Security Operations Center)**               | Information Security / Governance  | A centralized team and facility responsible for monitoring an organization's security posture, detecting anomalies, and responding to cyber threats in real-time.                                                  | A dedicated security command center that constantly watches over digital surveillance cameras and alarms to intercept intruders before they cause damage.   | Monitoring security logs through SIEM tools, investigating endpoint telemetry alerts (Sysmon/EDR), and handling incident responses.                                         | Maintain strict shift handovers, log analysis baselines, and rapid containment playbooks to minimize incident dwell time.                                           |
| **SOP (Standard Operating Procedure)**             | Governance / Operations            | A set of step-by-step instructions compiled by an organization to help workers carry out complex routine operations efficiently and in compliance with regulations.                                                | A crystal-clear recipe or instruction manual that ensures everyone cooks the exact same meal the exact same way, every single time.                         | Documenting repeatable system configurations, emergency patching protocols, user provisioning steps, and maintenance routines.                                              | Keep procedures concise, version-controlled in the PKM/OneNote repository, and subject to regular reviews for continuous improvement.                               |
| **SPOF (Single Point of Failure)**                 | System Architecture / Reliability  | A part of a system that, if it fails, will stop the entire system from working or cause a complete operational blackout.                                                                                           | The single load-bearing pillar in a house; if you knock it down, the entire roof caves in.                                                                  | Identifying non-redundant power supplies, single upstream routers, or dedicated storage nodes in infrastructure topologies.                                                 | Systematically audit architectures to eliminate SPOFs via clustering, load balancing, multi-path routing, and high-availability redundancy.                         |
| **Standardization**                                | Fleet Governance / Ops             | The enforcement of uniform protocols, naming conventions, and hardware/software configurations across an organization.                                                                                             | Getting every system, team, and machine to speak the exact same language and use the same baseline configurations.                                          | Enforcing strict dual-track file/ticket naming conventions and standardized baseline OS configurations across all fleet endpoints.                                          | Unifies operations across platforms, drastically reducing cognitive overhead and eliminating configuration drift during troubleshooting.                            |
| **Topology**                                       | Network Architecture               | The specific physical or logical arrangement of nodes, links, and connections that make up a computer network.                                                                                                     | The physical "map" or floor plan of exactly how all the cables and devices in a network are physically or virtually wired together.                         | Mapping physical cabling blueprints (Star, Mesh) or logical VLAN segments that control traffic routing between infrastructure layers.                                       | Maintain up-to-date physical wiring diagrams and logical network maps to accelerate isolation during outage triage.                                                 |
